"C 盘太小"是 Windows 用户最常见、也最容易被带偏的需求。市面上的扩容方案大致分三类：删分区重分配、用空闲空间直接扩容、用同盘其它分区的空闲空间挂载过来。很多教程只讲第一类能成功的情况，于是失败的人一脸茫然——"我的分区表明明有 200GB 未分配空间，为什么就是扩不上去？"

这篇按失败原因倒推，把三条路线各自的适用条件和失败征兆讲清楚。

## 路线一：删掉相邻分区，把空间并给 C

这是最经典、也是最容易被推荐的做法。

步骤不复杂：备份 → 删掉 C 右侧的 D 分区 → 右键 C 选"扩展卷" → 选那块未分配空间。前提条件只有一个：**未分配空间必须与 C 在物理上相邻，并且紧挨在 C 的右侧**。

失败征兆有三种，对应三种不同的原因：

- **"磁盘管理里没有扩展卷按钮"**：C 右侧没有紧邻的未分配空间，中间还夹着 E 或恢复分区。解法是先把夹在中间的卷也处理掉，代价很大。
- **"扩展卷是灰的，但旁边明明有黑条"**：那条黑条是"未分配"，但它可能是"分区尾部外空间"而不是"相邻空洞"。这两种黑条在界面上一模一样，含义却不同。
- **"扩展到一半提示磁盘已损坏/无效参数"**：分区表本身有错位，或者操作中途断电了。恢复分区（OEM 恢复分区、EFI、MSR）是最容易误删的一块。

这条路线最狠的一点是：**为了给 C 腾空间，你得先放弃另一个分区**。那个分区里有什么、有多大、多久不用，只有你知道。

## 路线二：把空闲空间直接并入现有卷（第三方分区工具）

这条路线的思路是：不动 C、不删任何分区，直接把磁盘上"没人用"的空间划给 C。

听起来无损，实际风险集中在两件事：

1. **分区表改写**：移动分区起始扇区时写错一个扇区，整块盘都可能读不出来。所以务必先做**整盘镜像备份**，而不是只备份 C 盘里的文件。
2. **BitLocker**：开了 BitLocker 的机器上直接动分区表会触发恢复密钥校验。没保存密钥的话，扩容之后系统可能根本进不去。

如果这两件事你都做到了（镜像备份 + 恢复密钥在手），这条路线确实是最省事的：不动数据、不删分区、C 盘直接变大。

## 路线三：不合并，把同盘空闲空间挂给 C

还有一种更保守的思路：C 盘本身不变大，但把同盘其它分区里的空闲空间，以文件夹（或挂载点）的形式挂到 C 盘下面。

它的适用场景很明确：**你缺的是可写空间，而不是总容量**。比如 C 盘只装了系统和软件，够用；但你要在里面放一个 80GB 的模型数据集、或者一个巨大的构建缓存，放不下。

这条路线的代价是访问路径多了一层：数据实际在 D 盘，只是通过 C 盘下的一个目录访问。好处是完全可逆——不写分区表、不动 BitLocker、不破坏恢复分区，出问题把挂载点删掉就回到原样。

我用的工具是 ScsExpand：https://expand.scsoi.com ，它做的是这一类事情——把同盘其它分区的空闲空间按需挂给 C 盘，文件留在原地，不做分区合并。

## 三条路线怎么选

按"你能承受多大代价"来排：

| 你能接受 | 建议路线 | 前置条件 |
|---|---|---|
| 完全不能动现有数据 | 路线三 | 同盘有别的分区且有空闲空间 |
| 有整盘镜像备份 + 恢复密钥 | 路线二 | C 右侧有可用的连续空闲区 |
| 能放弃一个分区 | 路线一 | 目标分区里没有你还需要的文件 |

## 动手前的四件事

不管走哪条，这四件事先做完，能省掉大部分返工：

1. `diskpart` 的 `list disk` / `list partition` 把真实分区表顺序抄下来，别信磁盘管理里的颜色；
2. 确认空闲区与 C 的**物理相邻关系**，以及是否被 OEM 保留分区切开；
3. 检查 BitLocker 状态，并把恢复密钥备份到 U 盘或打印出来；
4. 做整盘镜像备份（不是文件级备份）。

分区表是顺序敏感的结构：同一块空闲区，在不同的分区顺序下它是完全不同的东西。先把表看清楚再动手，比任何工具都重要。
